# Ecampus UniPlanner — Code Style

> Generated by Project Initializer. Documents conventions observed in the codebase. Three live languages: Kotlin Multiplatform (`shared/`), TypeScript/React (`web/`), Python (`parser/`). **UI text, comments, and error messages are Russian; code identifiers are English.**

## Naming Conventions

### TypeScript / React (`web/`)
| Thing | Convention | Example |
|---|---|---|
| Component files (JSX) | `PascalCase.tsx` | `web/src/pages/TodayPage.tsx`, `entities/task/ui/TaskRow.tsx` |
| Non-component modules | `camelCase.ts` | `httpClient.ts`, `queryClient.ts`, `date.ts` |
| shadcn/radix primitives | `kebab-case.tsx` | `web/src/shared/ui/button.tsx`, `input.tsx`, `badge.tsx` |
| Barrel re-exports | `index.ts` per folder | `shared/types/index.ts` |
| Components | named function declarations (never `const X = () =>`) | `export function TodayDashboard({ onSelectLesson }: TodayDashboardProps)` |
| Hooks | `useXxx` | `useAuth`, `useTasksQuery`, `useToggleTaskMutation` |
| Props types | `interface XxxProps` declared above the component | `TaskRow.tsx:14-17` |
| Query keys | factory objects: `xxxKeys.all`, `xxxKeys.list(id)` | `entities/task/model/queries.ts:6-9` |
| API modules | `export const xxxApi = { list, create, update, remove }` | `entities/task/api/taskApi.ts:16` |
| Request DTOs | `XxxInputDto` suffix (avoids TS structural clash with Kotlin-generated classes) | `taskApi.ts:7` |
| Constants | `UPPER_SNAKE_CASE` | `VITE_API_URL`, `API_BASE_URL` |

## File Organization

### Web — Feature-Sliced Design
```
src/
├── app/        # App.tsx, router, providers (AuthProvider)
├── pages/      # Route-level pages (Today, Schedule, Tasks, Notes, Login)
├── widgets/    # Composite UI (Layout, Sidebar, TodayDashboard)
├── features/   # feature slices: <domain>/<feature>/  (auth/login-form, schedule/week-switcher)
├── entities/   # per domain: api/, model/, ui/   (task/, note/, lesson/)
└── shared/     # api/, constants/, lib/, types/, ui/ (primitives), utils/, validators/
```
New feature recipe: copy the `entities/<domain>/` triad — `api/<name>Api.ts` (thin `apiClient` wrapper + `<name>InputDto`), `model/queries.ts` (`<name>Keys` + `use<X>Query` / `use<Verb><X>Mutation`), `ui/<Name>Card.tsx` (`interface <Name>CardProps` + named export).

### Parser — layered
```
app/
├── main.py              # FastAPI app; wire routers here with prefix="/api/v1"
├── api/endpoints/       # thin HTTP handlers
├── core/                # config, http client, cors, dependencies
├── services/            # business logic (parser/, auth/)
├── db/                  # session.py, base.py; models/ + repositories/
├── schemas/             # Pydantic DTOs
└── utils/ tests/        # standalone scripts, test helpers
```
New endpoint recipe: add `XxxRepository` (`async def upsert/upsert_many/get_*`) in `app/db/repositories/`, 4-layer Pydantic schema in `app/schemas/`, register router in `main.py`.

## Import Style

- **TypeScript**: external libs first, then `@/` internal (FSD order: `features` → `entities` → `shared`); `import type` for types; alias `@` → `./src` (`vite.config.ts:10-11`).
  ```tsx
  import { useState } from 'react';
  import { useSearchParams } from 'react-router-dom';
  import { WeekSwitcher } from '@/features/schedule/week-switcher/WeekSwitcher';
  import { useScheduleQuery } from '@/entities/lesson/model/queries';
  import { addDays } from '@/shared/lib/date';
  import type { Lesson } from '@/shared/types';
  ```
- **Python**: absolute imports from `app.*` package root — never relative (`from .`):
  `from app.services.parser import ParserOrchestrator`, `from app.core.dependencies import get_db_session`.
- **Kotlin**: stdlib/serialization first, then own config: `import kotlinx.serialization.Serializable` → `import ru.uniplanner.shared.config.API_BASE_URL`.

## Code Patterns

### React Query is mandatory for server state
- No manual `useEffect` data fetching. `useQuery`/`useMutation` only; `useEffect` reserved for one-time side effects (session restore in `AuthProvider.tsx:43-53`).
- Mutations invalidate keys on success: `onSuccess: () => queryClient.invalidateQueries({ queryKey: taskKeys.all })`.
- Components read `isLoading`/`data` and render Russian empty states (`Загрузка...`).

### Fetch wrapper (`shared/api/httpClient.ts`)
- Thin `fetch` client; attaches `Authorization: Bearer <token>` from `localStorage`; typed generics `apiClient.get/post/put/delete`; `204 → undefined`.

### Kotlin: value-object validation
- Validators accumulate errors into `mutableListOf<String>` and return `ValidationResult(isValid, errors)` — exceptions only via explicit `requireValid()`.

### Python: repository + orchestrator
- Repos take `AsyncSession` in `__init__`; injected via `Depends(get_db_session)`.
- Long parses run as FastAPI `BackgroundTasks`; endpoints stay thin.
- Retry transient network errors with tenacity: `@retry(stop=stop_after_attempt(3), wait=wait_exponential(...), retry=retry_if_exception_type((httpx.TimeoutException, httpx.NetworkError, httpx.HTTPStatusError)))` (`core/http_client.py:42-50`).

## Error Handling

- **Web**: errors are plain `Error` with Russian message thrown from the fetch client; caught in UI: `catch (err) { setError(err instanceof Error ? err.message : 'Не удалось выполнить запрос'); }`; auth failures clear token in provider `.catch()`.
- **Kotlin**: `ValidationResult` (no exceptions); throw only via `requireValid()`.
- **Python**:
  - API errors: `raise HTTPException(409, "Парсинг уже выполняется")`.
  - Fail-soft per entity: `_safe_parse` catches and returns `[]` (`orchestrator.py:244-251`).
  - Rollback on error in loops: `await self.db_session.rollback()` + `logger.exception(...)` (`orchestrator.py:184-192`).
  - Pydantic validators raise `ValueError` with Russian message (`schemas/lesson.py:30-37`).

## Logging

- **Python only** — module-level `logger = logging.getLogger(__name__)`; `%s`-style lazy formatting:
  ```python
  logger.info("Начинаем полный парсинг с %s по %s", start_date, end_date)
  ```
  Levels: `info` (lifecycle), `debug` (per-item progress), `warning` (stuck status), `exception` (in except blocks). Root config in `app/main.py:15-17` (`logging.basicConfig(level=logging.INFO, format="%(asctime)s - %(name)s - %(levelname)s - %(message)s")`).
- **Web/Kotlin**: no logging — errors surface via thrown `Error` / returned `ValidationResult`.

## Do's and Don'ts

**Do**
- Do write UI strings, comments, and error messages in Russian; identifiers in English.
- Do use react-query (`useQuery`/`useMutation`) for all web server state.
- Do use named function declarations for React components.
- Do use `import type` for type-only imports in TS.
- Do use absolute `from app.*` imports in Python.
- Do use 4-layer Pydantic schemas and `XxxRepository` classes in the parser.
- Do use `@Serializable` + `@JsExport` on every Kotlin model; keep them in sync with `api/*.yaml`.
- Do regenerate the KMP→web bridge after changing Kotlin models: `./gradlew buildJsDev`.

**Don't**
- Don't use relative imports (`from .`) in the parser.
- Don't write `const Component = () => ...` in web — use `export function`.
- Don't hand-edit `web/src/shared/kmp/dto/*` — it's generated and gitignored.
- Don't add a model to `ApiModels.kt` without the matching `validateXxx` in `ModelValidators.kt`.
- Don't confuse parser API fields (`camelCase`) with DB columns (`snake_case`).
- Don't create a new `web/src/shared/utils` module — use `shared/lib` (duplication exists today).
- Don't introduce an exception-based validation style in Kotlin — return `ValidationResult`.
