# Ecampus UniPlanner — Architecture

> Generated by Project Initializer. Documents the codebase as it exists today.

## Overview

Ecampus UniPlanner is a cross-platform student organizer. It provides a unified UI for viewing the university schedule (fetched automatically by scraping the university website), managing tasks and notes, and getting notifications. The repo is a polyglot monorepo: a Kotlin Multiplatform `shared` module, a React/TypeScript `web` client, and a Python FastAPI `parser` microservice. The Ktor `backend` is a stub (no source yet); the Android client is planned but absent.

## Core Components

### `api/` — API contract layer
- `openapi.yaml` is the master spec (servers: Ktor `:8080`, FastAPI `:8000`).
- Schemas and paths are split across `backend-api.yaml` (auth, tasks, notes, schedule, groups) and `parser-api.yaml` (institutes, specialties, groups, teacher, lessons, parser status/sync) and referenced via `$ref`.
- Bearer JWT auth scheme is declared here.

### `shared/` — Kotlin Multiplatform data models
- Hand-written `@Serializable` + `@JsExport` data classes mirroring the OpenAPI spec (Request/Response split: `Task`/`TaskInput`, `LoginRequest`/`LoginResponse`).
- `ModelValidators.kt` returns `ValidationResult(isValid, errors)` — no exceptions by default.
- `OpenApiValidationTest.kt` keeps models in sync with the spec.
- Compiled to a JS library (`shared.mjs` + `shared.d.mts`) and copied into `web/src/shared/kmp/dto/` by Gradle tasks (`copyJsToWebDev`/`copyJsToWebProd`).

### `web/` — React frontend
- Entry: `web/src/main.tsx` → `app/App.tsx` (QueryClientProvider → AuthProvider → AppRouter).
- Routes (`app/router.tsx`): `/login` public; `/`, `/schedule`, `/tasks`, `/notes` behind `ProtectedRoute` (token from localStorage).
- Data fetching exclusively via react-query (`useQuery`/`useMutation` with query-key factories) and a thin fetch wrapper `shared/api/httpClient.ts` that attaches `Authorization: Bearer <token>`.
- Uses Feature-Sliced Design layers: `app` → `pages` → `widgets` → `features/<domain>/<feature>/` → `entities/<domain>/` → `shared/`.
- `entities/<domain>/` follows a triad: `api/<name>Api.ts` + `model/queries.ts` + `ui/<Name>Card.tsx`.
- KMP bridge: types come from the generated `shared/kmp/dto/shared.d.mts`; hand-written `InputDto` interfaces avoid TS structural clashes with generated classes.

### `parser/` — Python FastAPI scraper microservice
- Scrapes the university information system (`https://ecampus.ncfu.ru/schedule`) using httpx + BeautifulSoup4, authenticated with session cookies from `cookies.json`.
- Layered: `api/endpoints` (thin) → `services/parser` (orchestrator + per-entity parsers) → `db/repositories` (SQLAlchemy async) → PostgreSQL.
- Long-running parses run via FastAPI `BackgroundTasks`; a `parser_status` table guards against concurrent runs (409 if running); app `lifespan` resets a stuck `running` status on boot.
- Exposes `/api/v1/parser/*` endpoints (run-full, run-incremental, status, institutes, specialties, groups).

### `backend/` — stub
- Only `.env` + empty `build/` exist. Not registered in `settings.gradle.kts`. README describes it as Ktor + Supabase/PostgreSQL + JWT, but nothing is implemented.

## Data Flow

```
api/*.yaml (OpenAPI contract)
   │  hand-written
   ▼
shared/ ApiModels.kt (@Serializable @JsExport) ── validated by OpenApiValidationTest
   │  ./gradlew buildJsDev → copyJsToWebDev
   ▼
web/src/shared/kmp/dto/shared.mjs + shared.d.mts   (generated, gitignored)
   │  import type { ... } from '@/shared/kmp/...'
   ▼
web/ React app ──fetch (Bearer token)──▶ backend API   http://localhost:8080/api/v1  (planned Ktor)
                                          ▲
parser/ FastAPI ──scrape──▶ ecampus.ncfu.ru (cookies.json session auth)
   │  PostgreSQL (asyncpg/SQLAlchemy)
   ▼
parser API   http://localhost:8000/api/v1/parser/*   (internal service)
```

- **Models:** OpenAPI spec → hand-written Kotlin models → compiled to JS → imported by React.
- **Web → Backend:** `httpClient.ts` adds `Authorization: Bearer <token>` from `localStorage`, talks to `/api/v1` (Ktor backend, not yet implemented).
- **Parser:** scrapes schedule data into its own PostgreSQL DB (`uniplanner_parser`), serves it via `/api/v1/parser/*` on port 8000. Schedule is per academic group.
- **UI text and error messages are Russian** throughout; identifiers are English.

## External Integrations

- **University website** (`https://ecampus.ncfu.ru/schedule`) — scraped by the parser; session auth via `cookies.json` file (`services/auth/cookie_file_auth.py`).
- **PostgreSQL** — parser DB (`asyncpg`), migrations via Alembic.
- **Ktor backend (planned)** — Supabase (PostgreSQL) + JWT per README; not implemented.
- **No** Docker, CI (GitHub Actions), or cloud deployment configs exist yet.

## Configuration

| File | Purpose |
|---|---|
| `gradle.properties` | `apiBaseUrl=http://localhost:8080/api/v1`, `requestTimeout=30000`, JVM args, config cache on |
| `shared/build.gradle.kts` | `buildConfig` injects `API_BASE_URL` (from `apiBaseUrl` property) into Kotlin `ApiConstants` |
| `web/.env` | `VITE_API_URL=http://localhost:8080/api/v1`, `VITE_PARSER_URL=http://localhost:8000/api/v1` |
| `parser/.env` (see `.env.example`) | `DB_HOST/PORT/NAME/USER/PASSWORD`, `CORS_ORIGINS`, `UNIVERSITY_BASE_URL`, `COOKIES_FILE_PATH`, `REQUEST_TIMEOUT`, `PORT=8000` |
| `backend/.env` | backend stub config (unused) |
| `web/vite.config.ts` | `@` alias → `./src`; react + tailwind plugins |

Parser settings are read via `pydantic-settings` (`app/core/config.py`, global `settings` instance); URLs are derived via properties (`database_url`, `async_database_url`, `cors_origins_list`).

## Build & Deploy

```bash
# Root — Gradle aggregate tasks (group "ecampus")
./gradlew showTasks          # list all available tasks
./gradlew buildJsDev         # :shared → JS dev library → copy to web/src/shared/kmp/dto
./gradlew buildJsProd        # same, production
./gradlew buildAllDev        # full dev build (shared only for now)
./gradlew cleanAll           # clean all build dirs + generated shared files in web
./gradlew rebuildJsDev       # cleanWebKmp → copyJsToWebDev

# Web
cd web && npm install        # (or npm ci)
npm run dev                  # Vite dev server (default :5173)
npm run build                # tsc -b && vite build
npm run lint                 # eslint .
npm run preview

# Parser
cd parser
python -m venv venv && venv/Scripts/activate
pip install -r requirements.txt
alembic upgrade head         # DB migrations (parser/alembic.ini)
uvicorn app.main:app --reload   # serves :8000, docs at /docs
```

> Note: `web/package.json` is named `web-tmp`; root `package.json` is an empty `{}` placeholder. No CI, Docker, or deployment configs exist.

## Known Gaps / Notes

- `backend/` and `android/` exist only on paper (README) — no source.
- `web/src/shared/utils/index.ts` vs `shared/lib/utils.ts` duplication.
- `parser/app/schemas/__init__.py` barrel is fully commented out; `db/models/__init__.py` is empty.
- Parser DB columns are `snake_case` while API/Pydantic fields are `camelCase` (by design, to mirror the JSON contract).
- Root README references `:shared:buildJsDevAndCopy` — the actual task name is `:shared:copyJsToWebDev`.
