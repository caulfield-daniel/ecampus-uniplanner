# Этап 03: База данных

## Обзор этапа

Спроектирована схема БД backend'а (`uniplanner_backend`), отдельная от БД микросервиса-парсера (`uniplanner_parser`). Миграции — Flyway, версии V1—V4.

## Артефакты

| Файл | Описание |
|---|---|
| [er-diagram.md](er-diagram.md) | ER-диаграмма, ограничения целостности, список миграций |

DDL — непосредственно в Flyway-миграциях `backend/src/main/resources/db/migration/V1__init_schema.sql` … `V4__add_lesson_links.sql` (отдельного дублирующего `ddl.sql` в docs не ведётся — миграции и есть единственный источник истины по схеме).

## Ключевые решения этапа

- `cached_lessons` денормализована относительно `users` (связь по `group_name`, не FK) — кэш расписания, наполняемый внешним парсером, не владеет связью с конкретным пользователем.
- Привязка задачи/заметки к занятию (`lesson_id`) — необязательная, `ON DELETE SET NULL`, чтобы удаление устаревшего занятия из кэша не приводило к потере пользовательских данных.
- Личные учётные данные ИС вуза (`university_credentials`) хранят только зашифрованную сессию (AES-GCM), не пароль.
