# Итоги проекта

## Реализовано

- Аутентификация: регистрация, логин (JWT), `/auth/me`.
- CRUD задач и заметок (привязаны к пользователю), опционально — к конкретному занятию расписания (`lessonId`), с бейджем дисциплины и фильтром по занятию на страницах «Задачи»/«Заметки».
- Личный логин пользователя в ecampus.ncfu.ru через капчу (`UniversityCredentialEntity`, шифрование сессии AES-GCM) — отдельно от сервисного аккаунта парсера. Backend-флоу готов и проверен через API; экран в интерфейсе приложения не реализован (см. [09-user-guide/user-guide.md](../09-user-guide/user-guide.md)).
- Синхронизация кэша расписания: backend сам забирает (pull) у parser'а уже накопленные данные (`ParserClient` + `ParserSyncController`, `POST /parser/sync`) — проверено массово: все 866 групп, известных парсеру, синхронизированы (44695 занятий, реальные данные вуза за март–апрель 2026). Инструкция по ручному запуску до появления админ-панели — [08-deployment/admin-guide.md](../08-deployment/admin-guide.md).
- React-клиент на FSD-архитектуре (TanStack Query, shadcn/ui, Tailwind v4): дашборд «Сегодня», расписание по неделям с фильтром по предмету, слайд-панель занятия с задачами/заметками, полные страницы задач/заметок. См. [07-ui/screens.md](../07-ui/screens.md).
- Тесты сервисного слоя (32 теста, MockK, JUnit5), JaCoCo. См. [06-testing/tests.md](../06-testing/tests.md).
- Docker Compose для backend + PostgreSQL — развёрнуто и проверено живьём (Flyway применил миграции V1—V4, golden path пройден вручную в браузере).

## Осознанные упрощения (для прозрачности на защите)

- Авторизация **сервисного** аккаунта парсера (для скрейпинга публичного расписания групп) — простой cookie-файл, экспортируемый вручную; реальная капча на сайте вуза реализована только для **личного** логина пользователей (другой флоу, `parser/app/services/auth/captcha_login.py`).
- Экран для личного входа в ИС вуза (`/university-auth/*`) не реализован во фронтенде — функциональность доступна через API/Swagger, не из интерфейса приложения.
- Запуск синхронизации расписания (`POST /parser/sync`) — вручную, без cron; задача на будущее, если потребуется автообновление.
- Адаптивная вёрстка React — desktop-first, мобильная раскладка не доделана.
- Вкладка «Файлы» в детальной панели занятия убрана совсем — у backend нет file storage.
- `relatedLessonId` в TS-типах фронтенда расширен локальной аугментацией (`web/src/shared/types/index.ts`), а не сгенерированным `.d.mts` — генерация TypeScript-деклараций из Kotlin/JS была нестабильна на машине разработки в моменте (см. [05-implementation/code-structure.md](../05-implementation/code-structure.md)).
- Бейдж и фильтр по занятию на страницах «Задачи»/«Заметки» резолвят `lessonId` через широкое окно `GET /schedule` (±180 дней), а не через отдельный backend-эндпоинт «занятие по id» — сознательное упрощение, не требующее изменения API.
