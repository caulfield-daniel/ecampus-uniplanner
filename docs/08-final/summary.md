# Итоги (промежуточный статус прототипа)

## Реализовано

- Аутентификация: регистрация, логин (JWT), `/auth/me`.
- CRUD задач и заметок (привязаны к пользователю), опционально — к конкретному занятию расписания (`lessonId`).
- Личный логин пользователя в ecampus.ncfu.ru через капчу (`UniversityCredentialEntity`, шифрование сессии AES-GCM) — отдельно от сервисного аккаунта парсера.
- Синхронизация кэша расписания: backend сам забирает (pull) у parser'а уже накопленные данные (`ParserClient` + `ParserSyncController`, `POST /parser/sync`) — проверено живым запросом на реальных данных вуза.
- React-клиент на FSD-архитектуре (TanStack Query, shadcn/ui, Tailwind v4): дашборд «Сегодня», расписание по неделям с фильтром по предмету, слайд-панель занятия с задачами/заметками, полные страницы задач/заметок. См. `docs/07-ui/screens.md`.
- Тесты сервисного слоя (MockK, JUnit5), JaCoCo.
- Docker Compose для backend + PostgreSQL.

## Осознанные упрощения (для прозрачности на защите)

- Авторизация **сервисного** аккаунта парсера (для скрейпинга публичного расписания групп) — простой cookie-файл, экспортируемый вручную; реальная капча на сайте вуза реализована только для **личного** логина пользователей (другой флоу, `parser/app/services/auth/captcha_login.py`).
- Запуск синхронизации расписания (`POST /parser/sync`) — вручную, без cron; задача на будущее, если потребуется автообновление.
- Адаптивная вёрстка React — desktop-first, мобильная раскладка не доделана.
- Вкладка «Файлы» в детальной панели занятия убрана совсем — у backend нет file storage.
- `relatedLessonId` в TS-типах фронтенда расширен локальной аугментацией (`web/src/shared/types/index.ts`), а не сгенерированным `.d.mts` — генерация TypeScript-деклараций из Kotlin/JS была нестабильна на машине разработки в моменте (см. `docs/06-implementation/notes.md`).
