# Итоги (промежуточный статус прототипа)

## Реализовано

- Аутентификация: регистрация, логин (JWT), `/auth/me`.
- CRUD задач и заметок (привязаны к пользователю).
- Чтение расписания и списка групп (читает локальный кэш `cached_lessons`).
- React-клиент: 5 страниц (Login, Tasks, TaskForm, Notes, Schedule), защищённые роуты, тонкий fetch-клиент с JWT.
- Тесты сервисного слоя (MockK, JUnit5), JaCoCo.
- Docker Compose для backend + PostgreSQL.

## Осознанные упрощения (для прозрачности на защите)

- **Парсер не интегрирован вживую.** `cached_lessons` заполняется seed-миграцией (`V2__seed_demo_lessons.sql`), а не реальным синком с FastAPI-парсером. Эндпоинты `POST /parser/sync`/`GET /parser/status` и `Foundation.ParserClient` — не реализованы в этой итерации.
- Авторизация парсера в ИС вуза — простой cookie-файл; известно, что реальная система использует капчу, парсинг капчи — будущая задача (не в скоупе текущего прототипа).
- React-вёрстка минимальна (без адаптивности/дизайн-системы) — приоритет отдан работающей функциональности.
- Редактирование задачи получает данные через `location.state` (передаётся со страницы списка), а не через отдельный `GET /tasks/{id}` — упрощение, отдельный эндпоинт не реализован.

## Дальнейшие шаги (если останется время)

1. `ParserClient` (Foundation) + `IParserSyncService` (Mediator) + `ParserSyncController` — реальная интеграция с FastAPI-парсером.
2. Адаптивная вёрстка React.
3. Android-клиент на базе KMP shared-модуля (бонус «дополнительный клиент»).
4. Капча-парсинг авторизации в ИС вуза (см. известное ограничение парсера).
