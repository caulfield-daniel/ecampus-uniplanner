# Спецификации вариантов использования

## UC-01: Зарегистрироваться

- **Актёр:** Студент
- **Предусловия:** email не зарегистрирован в системе
- **Основной поток:** пользователь вводит email, пароль, ФИО, группу → `POST /auth/register` → пароль хешируется (BCrypt) → создаётся `UserEntity` с ролью `ROLE_USER`
- **Альтернативный поток:** email уже занят → `409 Conflict`
- **Постусловия:** аккаунт создан; пользователь должен дополнительно войти (UC-02)

## UC-02: Войти в систему

- **Актёр:** Студент
- **Предусловия:** аккаунт зарегистрирован
- **Основной поток:** email + пароль → `POST /auth/login` → проверка пароля → выдаётся JWT → фронтенд сохраняет токен (`localStorage`) и переходит на дашборд «Сегодня»
- **Альтернативный поток:** неверный пароль/email не найден → `401 Unauthorized`
- **Постусловия:** все последующие запросы несут `Authorization: Bearer <token>`

## UC-03: Просмотреть расписание

- **Актёр:** Студент
- **Предусловия:** пользователь авторизован; для группы пользователя есть данные в `cached_lessons`
- **Основной поток:** `GET /schedule?group=&from=&to=` за выбранную неделю → список занятий по дням; клик на занятие открывает детальную панель (включает UC-06)
- **Альтернативный поток:** для группы нет данных за период → пустой список, сообщение «На этой неделе занятий нет»
- **Постусловия:** —

## UC-04: Управлять задачами

- **Актёр:** Студент
- **Предусловия:** пользователь авторизован
- **Основной поток:** создание (`POST /tasks`) / редактирование (`PUT /tasks/{id}`) / удаление (`DELETE /tasks/{id}`) / отметка выполнения; опционально включает UC-06 (привязка к занятию)
- **Бизнес-правило:** `priority ∈ [1,5]` — инвариант проверяется в `TaskEntity.init`
- **Постусловия:** список задач обновлён, TanStack Query инвалидирует кэш

## UC-05: Управлять заметками

- **Актёр:** Студент
- **Аналогично UC-04**, но без приоритета/дедлайна — только заголовок и текст; опционально включает UC-06

## UC-06: Привязать задачу/заметку к занятию

- **Актёр:** Студент
- **Предусловия:** занятие существует в `cached_lessons` (видно в расписании)
- **Основной поток:** при создании/редактировании задачи или заметки из детальной панели занятия (`LessonDetailSheet`) поле `relatedLessonId` предзаполняется и скрыто от пользователя
- **Альтернативный поток:** создание задачи/заметки без привязки — `relatedLessonId = null`, доступно с обычных страниц «Задачи»/«Заметки»
- **Постусловия:** `GET /tasks?lessonId=`/`GET /notes?lessonId=` возвращают привязанные элементы; на страницах «Задачи»/«Заметки» элемент помечен бейджем дисциплины и доступен в фильтре по занятию

## UC-07: Синхронизировать расписание группы

- **Актёр:** Менеджер группы (вручную, без cron)
- **Предусловия:** парсер уже накопил данные по группе в своей БД
- **Основной поток:** `POST /parser/sync?group=&from=&to=` → backend забирает уже распарсенные занятия у микросервиса-парсера через `ParserClient` → сохраняет/обновляет `cached_lessons`
- **Постусловия:** расписание группы в кэше backend актуализировано; число синхронизированных занятий возвращается в ответе

## UC-08: Подключить личный аккаунт ИС вуза

- **Актёр:** Студент
- **Предусловия:** пользователь авторизован в приложении
- **Основной поток:** `POST /university-auth/captcha` → получение капчи → пользователь вводит код → `POST /university-auth/login` (email/пароль ИС вуза + код капчи) → сессия ИС вуза шифруется (AES-GCM) и сохраняется как `UniversityCredentialEntity`
- **Альтернативный поток:** неверная капча/учётные данные → ошибка, попытка не засчитывается (см. `attempt_store.py` в парсере)
- **Постусловия:** аккаунт пользователя привязан к личному логину в ecampus.ncfu.ru

## UC-09: Просмотреть/отключить привязку личного аккаунта

- **Актёр:** Студент
- **Основной поток:** `GET /university-auth/status` — статус привязки; `DELETE /university-auth/link` — отключение
- **Постусловия:** при отключении зашифрованные учётные данные удаляются из `UniversityCredentialEntity`
